# ARTEM.STUDY

Отдельный Go-проект для оффлайн-занятий Артема. Сайт и Telegram-интеграция работают с одной PostgreSQL. Есть два режима: подключение к существующему боту портфолио с сохранением его функций и отдельный процесс бота LMS.

Цвета взяты из `artem-updated.zip`, `assets/css/style.css`: фон `#222222`, текст `#EAE2B7`, акцент `#f67f00`. Интерфейс на русском, без эмодзи. Фронтенд на HTML/CSS/JavaScript встроен в Go-бинарник через `embed`.

## Что работает

- Кабинет преподавателя и отдельные кабинеты учеников; доступ ученика только к своим данным.
- Ученики: имя, телефон, направление, личные заметки преподавателя, логин, архивирование, сброс пароля.
- Расписание индивидуальных оффлайн-занятий: адрес, начало и конец, стоимость, перенос, отмена, пропуск и отметка проведения.
- Еженедельное повторение до 12 недель. Серия создается целиком либо не создается, если хотя бы одно занятие пересекается с другим.
- Домашние задания: текст, срок, ссылка на материалы, ответ ученика, ссылка на запись/файл, статус и комментарий преподавателя.
- Учет полученных оплат, авансов и долга. Ошибочная запись отменяется с указанием причины и остается в истории.
- Telegram: расписание на 14 дней, занятия на сегодня, открытые ДЗ, баланс, ссылка на кабинет. У преподавателя общие данные, у ученика личные.
- Одноразовая привязка Telegram на 30 минут, отключение привязки, отдельный администратор по Telegram user ID.
- Адаптивная верстка, защита сессий и изменений через CSRF, хеширование паролей bcrypt, секреты через окружение.

Это учет оплат, а не интернет-эквайринг. Сайт не принимает карты и не выполняет денежные переводы. ДЗ используют ссылки на внешние файлы; загрузки аудио и видео в LMS в этой версии нет. Ответы на ДЗ отправляются через кабинет, в Telegram задания доступны для чтения. Автоматические уведомления и напоминания не включены.

Расписание рассчитано на одного преподавателя и индивидуальные занятия. Групповые встречи, несколько преподавателей, абонементы, правила платного пропуска и онлайн-эквайринг потребуют отдельного расширения модели.

## Быстрый запуск

Нужны Docker Engine и Docker Compose. Рабочая директория отдельная, например `/opt/artem-study`. Порт `8083` выбран отдельно от портфолио.

```bash
cp .env.example .env
chmod 600 .env
openssl rand -hex 24
```

Запишите полученное значение в `POSTGRES_PASSWORD`, придумайте отдельный `ADMIN_PASSWORD` любой непустой длины, не более 72 байт. В URL подключения пароль БД должен быть URL-безопасным; шестнадцатеричная строка из команды подходит. Не оставляйте значения `replace_with_...` из примера.

Для локальной проверки оставьте:

```dotenv
PUBLIC_URL=http://localhost:8083
COOKIE_SECURE=false
```

Запустите сайт и базу без Telegram:

```bash
docker compose up -d --build
docker compose logs -f web
```

Откройте `http://localhost:8083`. Логин по умолчанию `artem`, пароль из `.env`. Первая учетная запись преподавателя создается автоматически только при первом запуске. Последующее изменение `ADMIN_PASSWORD` в `.env` не меняет пароль существующего администратора; меняйте его через настройки кабинета.

При работе с удаленным сервером можно проверить через SSH-туннель:

```bash
ssh -L 8083:127.0.0.1:8083 USER@SERVER
```

Затем откройте `http://localhost:8083` на своем компьютере. Снаружи порт Docker не опубликован: он привязан к `127.0.0.1`.

## Домен и HTTPS

1. Создайте отдельный поддомен, направленный на сервер.
2. Возьмите конфигурацию `deploy/nginx.conf`, замените `study.example.ru` на фактический домен и подключите ее в Nginx.
3. Проверьте `nginx -t`, перезагрузите Nginx и выпустите сертификат через `certbot --nginx -d ВАШ_ДОМЕН`.
4. В `.env` задайте точный адрес без пути и завершающего слеша:

```dotenv
PUBLIC_URL=https://ВАШ_ДОМЕН
COOKIE_SECURE=true
```

```bash
docker compose up -d web
```

`PUBLIC_URL` должен совпадать с адресом браузера. При открытии через другой домен операции записи будут отклонены защитой Origin. Не выключайте эту проверку для исправления домена: исправьте настройку.

Приложение использует часовой пояс `Europe/Moscow` независимо от часового пояса браузера и сервера. Его можно изменить через `APP_TIMEZONE`. Время явно подписано в формах и боте.

## Telegram-бот

ARCHIKILLA-STUDY использует отдельного Telegram-бота. Он запускается как самостоятельный polling-процесс и работает с той же PostgreSQL, что и сайт. Никаких bridge, webhook или старого portfolio-бота не требуется.

В `.env` задайте:

```dotenv
TELEGRAM_BOT_TOKEN=TOKEN_НОВОГО_БОТА
TELEGRAM_BOT_USERNAME=USERNAME_НОВОГО_БОТА
TELEGRAM_ADMIN_ID=TELEGRAM_ID_АДМИНИСТРАТОРА
```

Запуск сайта и бота:

```bash
docker compose --profile bot up -d --build
```

Проверка:

```bash
docker compose --profile bot ps
docker compose --profile bot logs --tail=100 bot
```

## Первое занятие

1. В разделе «Ученики» создайте карточку с логином и временным паролем. Передайте их ученику лично.
2. Добавьте занятие, стоимость и адрес. Для регулярных встреч укажите количество недель, включая первую.
3. Выдайте ДЗ. Ученик увидит его в кабинете и после подключения в боте.
4. В карточке ученика нажмите Telegram и передайте одноразовую ссылку. Ученик должен открыть ее именно со своего аккаунта.
5. После урока измените статус на «Проведено». Стоимость попадет в начисления.
6. После получения денег внесите оплату. Частичные платежи и авансы учитываются автоматически.
7. Проверьте ответ на ДЗ, напишите комментарий и выберите «Проверено». Для доработки верните статус «Выдано».

`Долг = стоимость проведенных занятий - действующие оплаты`. Если результат отрицательный, показывается аванс. Будущие занятия, отмены и пропуски не начисляются. Возврат проведенного занятия в другой статус убирает начисление. Изменение стоимости проведенного занятия также меняет итог. При отмене оплаты деньги физически не возвращаются: отменяется только запись в учете.

## Репозиторий и структура

```text
cmd/server/             HTTP-сервер
cmd/bot/                Telegram long polling
internal/app/           модель, SQL, авторизация и API
internal/bot/           команды и транспорт Telegram
internal/web/static/    HTML, CSS и JavaScript кабинета
deploy/nginx.conf       пример reverse proxy
docs/                   миграция бота и отчет проверки
compose.yaml            PostgreSQL, web и bot
.github/workflows/      сборка и интеграционные проверки
```

Новый репозиторий не содержит старую историю, медиа, `.env` или секреты портфолио. В архиве есть исходники и `artem-study.bundle` с первым коммитом. Чтобы получить готовый локальный Git-репозиторий:

```bash
git clone artem-study.bundle artem-study
cd artem-study
```

Или используйте папку исходников из архива:

```bash
cd artem-study
git init -b main
git add .
git commit -m "Initial Artem Study LMS"
```

Для публикации создайте пустой приватный репозиторий `artem-study` в своем аккаунте GitHub без README и затем:

```bash
git remote add origin git@github.com:YOUR_ACCOUNT/artem-study.git
git push -u origin main
```

Если вы использовали `git clone artem-study.bundle`, remote `origin` уже указывает на файл bundle. Вместо `git remote add origin ...` выполните `git remote set-url origin git@github.com:YOUR_ACCOUNT/artem-study.git`.

Удаленный репозиторий в GitHub в рамках подготовки архива не создавался.

## Разработка и проверка

Нужны Go 1.26+ и PostgreSQL 16. База должна разрешать создание расширения `btree_gist` для защиты расписания от пересечений. Docker Compose создает отдельную базу с нужными правами. На внешней PostgreSQL расширение может потребовать предварительной установки администратором.

```bash
go mod download
go test -race ./...
make build
```

Интеграционный тест создает отдельную схему и удаляет только ее. Используйте отдельную тестовую базу, не production:

```bash
TEST_DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/artem_test?sslmode=disable' go test -race ./...
```

Для запуска без Docker задайте переменные окружения и запустите `go run ./cmd/server`. `.env` читает Docker Compose; Go-процесс сам файл не загружает.

```bash
export DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/artem_study?sslmode=disable'
export PUBLIC_URL='http://localhost:8083'
export COOKIE_SECURE=false
export ADMIN_LOGIN=artem
export ADMIN_PASSWORD='YOUR_LONG_UNIQUE_PASSWORD'
go run ./cmd/server
```

После успешного старта сервера можно запускать `go run ./cmd/bot` с теми же настройками БД и Telegram. Бот сам не выполняет миграцию; сначала должен стартовать сервер.

## Резервная копия

```bash
mkdir -p backups
docker compose exec -T db pg_dump -U artem -d artem_study -Fc > backups/artem_study.dump
```

Храните резервные копии вне репозитория и периодически проверяйте восстановление в отдельную базу. Пароли сессий, Telegram-привязки и контакты учеников находятся в БД. Не публикуйте дамп. `docker compose down` сохраняет данные, а `docker compose down -v` удаляет том базы, поэтому для обычного обновления второй вариант не используйте.

Обновление без удаления данных:

```bash
git pull
docker compose up -d --build web
docker compose --profile bot up -d --build bot
```
