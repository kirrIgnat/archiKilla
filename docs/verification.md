# Проверка перед передачей

Проверена первая версия ARTEM.STUDY, 11 октября 2026 года.

## Успешные проверки

- Сборка `cmd/server` и `cmd/bot` через `make build`, Go 1.26.9, Linux amd64, CGO отключен.
- `go test -race -p 1 -v ./...` с тестовой PostgreSQL-совместимой базой на движке PGlite и режимом simple protocol в тестовом DSN.
- Повторный запуск миграции.
- Вход администратора и ученика, блокировка неавторизованных запросов, CSRF и запросов с другого Origin.
- Создание учеников, защита личных заметок и чужих данных.
- Отклонение пересечения занятий, допустимость соседних интервалов, откат всей серии при конфликте.
- Запрет отметки будущего занятия проведенным.
- Начисление за проведенный урок, частичная оплата, расчет долга.
- Идемпотентность платежа, отклонение повторного ключа с другой суммой, отмена платежа и пересчет.
- Создание ДЗ, ответ ученика, проверка преподавателем, запрет ответа на чужое ДЗ и изменения проверенной работы.
- Одноразовая Telegram-привязка, отклонение повторного использования, отключение привязки, изоляция данных.
- Архивирование ученика закрывает действующие веб-сессии и запрещает повторный вход.
- Telegram API ошибки 429, скрытие токена из сетевых ошибок, разбиение длинного текста без потери Unicode, игнорирование групповых сообщений.
- Патч bridge применен к исходному `admin_bot.go` из сохраненного проекта; измененный Go-проект портфолио успешно собран.
- Bridge-endpoint: отклонение запросов без общего секрета и некорректного JSON.
- JS-синтаксис через `node --check`.
- DOM-проверка двух ролей в jsdom: открытие разделов, форм ученика/занятия/ДЗ/оплаты, отправка основных форм, преобразование сумм и московского времени.
- Синтаксис YAML для Docker Compose и CI.
- В исходниках нет прежних Telegram-токенов и эмодзи.

## Границы проверки

Тесты выполнялись в изолированной среде. Полный Docker Compose с PostgreSQL 16, Nginx, HTTPS и живым Telegram API здесь не запускался. Для настоящего PostgreSQL 16 подготовлен GitHub Actions workflow с сервисом БД; он выполнится после публикации репозитория.

PGlite использует движок PostgreSQL, но не заменяет проверку конкурентных подключений на обычном сервере PostgreSQL. В автоматической проверке использовался simple protocol, поскольку prepared statements поверх тестового адаптера сокетов иначе конфликтуют после отката транзакции. В production DSN этот параметр не требуется.

Визуальная проверка в браузере не выполнялась; DOM-проверка не подтверждает фактический вид на всех размерах экрана.

На сервер пользователя код не устанавливался. Рабочий Telegram-бот не переключался. Удаленный GitHub-репозиторий не создавался.
